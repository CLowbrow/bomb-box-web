# Working in bomb-box-web

This repository is the static browser host and level editor for the Bomb Box rules engine. Keep
gameplay authority in the `bomb-box-state` submodule; the web layer should submit commands, consume
engine results, and present them rather than reconstructing rules.

## Repository map

- `site/app.js`: game bootstrap, controls, level selection, engine lifecycle, and console logging.
- `site/game/command-runner.js`: command serialization and busy-state handling.
- `site/game/tick-playback.js`: presentation of authoritative tick snapshots.
- `site/game/scene-model.js` and `three-view.js`: Three.js scene data and rendering.
- `site/game/config.js`: presentation timing such as `TICK_DURATION_MS`.
- `site/level-source.js`: canned-level discovery and editor-to-game handoff.
- `site/editor/`: Preact editor UI, reducer, normalized domain model, and local storage.
- `site/levels/canned/`: levels exposed in the game picker. Numeric filename prefixes determine
  order and are removed from display names.
- `site/levels/hardening-run.json`: broad gameplay fixture used for regression coverage, not the
  player-facing level picker.
- `tests/`: Vitest unit/component coverage plus static build integration checks.
- `docs/level-editor-development.md`: detailed editor architecture and behavioral contracts.
- `scripts/build.mjs`: builds the engine's `wasm-debug` preset, runs Vite, and assembles `dist/`.
- `bomb-box-state/`: Git submodule containing the C++ engine, schemas, adapters, and contract tests.
  Read its own `AGENTS.md` before changing anything inside it.

## Architectural invariants

- The C++ engine is authoritative for movement, physics, outcomes, rewind, level decoding, and
  validation. Do not infer or duplicate those rules in browser code.
- Each accepted command is atomic at the API boundary. Present the returned tick snapshots in
  order, matching entities by ID across states. Rewind is presented as one equivalent transition.
- Respect `prefers-reduced-motion`; it skips animation timing. Normal tick duration is configured
  in `site/game/config.js`.
- Restart reloads the authored level and clears engine history. Rewind uses the engine's resolved
  state history.
- The editor authors version 1 `game-rules-level` JSON. It may preserve invalid intermediate edits,
  but playtest and export actions stay unavailable until the engine accepts the draft.
- Editor autosave is device-local recovery, not authoritative or hosted persistence. Playtesting
  uses the versioned same-origin handoff documented in `docs/level-editor-development.md`.
- Keep asset URLs relative so the static output works at a custom domain or a GitHub Pages
  repository path.
- Do not hand-edit `dist/`; it is regenerated by the build.

## Rendering and fixtures

The board uses one scene unit per horizontal cell and 0.65 scene units per logical entity or
elevation level. Preserve exact half-step and stack relationships when changing the presentation.
Gameplay events and derived ticks are logged to the browser console for inspection.

`site/levels/hardening-run.json` preserves the original thirteen-turn integration path: pushing,
falling, barrel arming and chain explosions, switches and doors, walking on a raised box, ramps,
winning, exact rewind, and branching after rewind. Update it deliberately when changing its role.

## Verification

- `npm run test:unit`: browser and editor unit/component tests.
- `npm run test:wasm`: WebAssembly adapter contract corpus.
- `npm run test:site`: generated-site integration checks.
- `npm test`: full build and all of the above; use this before handing off cross-cutting changes.

The build requires Node.js 22.12+, CMake 3.25+, Ninja, Emscripten, and an initialized submodule.
Avoid editing generated engine output under `bomb-box-state/out/`.
